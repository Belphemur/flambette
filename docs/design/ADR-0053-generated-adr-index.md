# ADR-0053 — the ADR index is generated, and AGENTS.md links it

* Status: **Accepted** (as built)
* Companions: `scripts/build_adr_index.py`, `scripts/test_build_adr_index.py`,
  `docs/design/index.md`, `docs/design/README.md`, `AGENTS.md`,
  `.github/workflows/ci.yml`, `package.json`

## Context

`AGENTS.md` carried a hand-maintained paragraph listing the "notable" ADRs
in prose — twenty-odd decisions described in a sentence and a half each,
inside a bullet about conventions. Two problems, both of which had already
cost time.

**It drifted silently.** An ADR landing never edited the list, so the list
was always behind, and nothing could tell. The paragraph had already gone
stale enough that ADR-0052 existed only because it was appended by hand in
the same commit that created it.

**It was the wrong shape.** A prose summary of 57 files is a lossy copy: it
can only hold what someone remembered to mention, and an agent reading
`AGENTS.md` learns about a handful of decisions while 46 others are
invisible. Meanwhile the *actual* list of records lived nowhere — there was
no index at all, only `ls docs/design/`.

The numbering made it worse. **57 files share 52 numbers**: ADR-0027 is
used three times (`auto-plan-v2`, `unified-quick-filters`,
`preview-hosting`), and ADR-0038, ADR-0039 and ADR-0040 are each used
twice. Records are cited as bare numbers throughout the codebase — `grep`
finds 201 citation lines — and the two records sharing ADR-0038 are cited
in *different files about different subjects* (`server/relay-core/policy.ts`
means the Cloudflare TTLs; `ADR-0041` means the timer-strip reshape). A bare
`ADR-0038` is therefore genuinely ambiguous, and nothing in the repo said
so.

The cause is mundane: numbering a new record by counting the files. With 57
files sharing 52 numbers, `count + 1` yields a number already in use.

## Decision

**`docs/design/index.md` is GENERATED by `scripts/build_adr_index.py`, and
`AGENTS.md` links it instead of restating it.**

Following the pattern every other committed artifact in this repo already
uses (`extract_ingredients.py`, `extract_recipe_types.py`,
`extract_timer_hints.py`): a stdlib-only generator, a committed output, a
`--check` mode, and goldens.

- **The index is generated, never hand-edited.** It lists every record with
  title, status bucket and date, split into *In force* and *Not in force*.
  A record's `Supersedes:` line is resolved into an inline
  `_(supersedes ADR-NNNN)_` annotation.
- **`AGENTS.md` links it.** Adding an ADR touches the new file, the
  regenerated index, and nothing else. This is the property the owner asked
  for: *we don't need to keep updating the agents.md*.
- **`--next` prints the next free number, and it is `max + 1`, never
  `count + 1`.** Max is correct under duplicates; count is only correct when
  numbering is dense, which is the assumption that broke. A golden pins the
  arithmetic, because this is the exact bug that produced the collisions.
- **Dates fall back to git.** Three records (ADR-0036, ADR-0042, ADR-0052)
  carry no `Date:` line and the folder is inconsistent about the field.
  Rather than invent dates in the records, the generator asks
  `git log --diff-filter=A` when the file landed. A golden asserts every row
  resolves to a real date, so the fallback cannot silently stop working.
- **The existing collisions are DISCLOSED, not renumbered.** The index has
  its own *Known numbering collisions* section naming all four. Renumbering
  would break 201 citation lines, the ADR bodies and every commit message
  that references a number — a deliberate migration, not a regeneration.
  The rule going forward is `--next`; the fix, if wanted, is its own ADR.
- **Status is bucketed, not echoed.** Records write status as prose
  (`accepted (2026-09-29)`, `accepted (share URL 2026-09-23;
  superseded-in-part by ADR-0051)`). The index collapses that to four
  buckets, because the question an agent asks before skimming is *does this
  still govern* — a supersession question, not a date question.

## Consequences

- `AGENTS.md` no longer lists ADRs, so it stops needing edits per record. A
  golden enforces this: it fails if the *Design ADRs* bullet grows back
  into a list (more than two bare ADR numbers), and if the index link
  disappears.
- CI gains a `Committed ADR index is not stale` step beside the existing
  ingredient-index check, and `test:data` now runs the new goldens.
- The goldens read the **committed** `index.md` and compare a fresh build
  against it. They never regenerate first: a gate that refreshes its own
  subject cannot fail on a stale file, and `index.md` is exactly what
  `AGENTS.md` points readers at. Verified by tampering one link — the
  staleness, completeness and broken-link goldens all fail, and `--check`
  exits 1.
- `docs/design/README.md` points at the index, so the folder is
  self-describing to someone who opens it directly.
- **Costs:** one more generated file in the repo, and one more Python
  process in `test:data` (~0.4 s). `git log` is consulted for the three
  dateless records, so the generator needs a checkout; outside one it
  degrades to `—` and the date golden fails loudly rather than shipping a
  blank.
- **Not fixed here:** the four pre-existing collisions. They are recorded,
  and `--next` prevents new ones.

## Alternatives considered

- **Renumber the colliding records now.** Rejected for this change: 201
  citation lines, and the shared numbers are cited in different files about
  different subjects, so each one needs individual disambiguation rather
  than a find-replace. Worth doing as its own ADR with its own
  verification, not as a side effect of generating an index.
- **Generate the index but keep the `AGENTS.md` prose too.** Rejected: two
  lists, one of which can still drift. The prose was the stale copy.
- **Derive the next number from `count + 1`.** Rejected: it is the bug. With
  57 files sharing 52 numbers it returns 0058 — free *today*, so it fails
  quietly rather than loudly, and it burns 0053–0057 permanently. The moment
  a record lands at 0058 (or any number past the count), `count + 1` hands
  out a number already in use. `max + 1` is correct under duplicates, which
  is the only condition we are in.
- **Read dates from the records only, and add `Date:` to the three missing
  ones.** Rejected in favour of the git fallback: the folder's header
  convention is already inconsistent, and a generator that hard-fails on a
  missing optional field gets worked around rather than fixed. The git
  fallback removes the failure mode instead.
